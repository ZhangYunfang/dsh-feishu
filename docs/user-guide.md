# dsh-feishu 用户指南

> 给**使用**这个插件的人：怎么让 DSH 里的 agent 替你在飞书里干活。
> 安装见 [`install-for-others.md`](./install-for-others.md)；能力与权限对照见 [`feishu-capabilities.md`](./feishu-capabilities.md)。
> 版本 0.1.3 · 实测宿主 DeepSeek Harness `0.1.2-alpha.2`

---

## 1. 一句话心智模型

你**不需要记 API**。装好后 DSH 里多了 10 个工具（`feishu_*`），你用中文说要做的事，agent 自己挑工具、拼参数、把结果告诉你。

```text
你：在飞书里建一个 Base，叫「周报统计」，字段是 姓名/日期/工时，然后插 3 条示例数据
agent：（依次调 feishu_bitable create_app / insert_records）→ 建好了，链接 https://…/base/xxx
```

三个概念先记住，后面遇到问题都靠它们定位：

| 概念 | 含义 | 对你的影响 |
|---|---|---|
| **身份（identity）** | `user`＝以**你本人**身份操作（文档落你云空间）；`app`＝以应用身份（落应用空间）；`auto`＝优先你，没授权就用应用并**告警** | 想要"东西在我的飞书里"，就要有用户授权（§2） |
| **应用权限** | 开发者后台勾选 + **创建版本发布** | 后台改了不发版＝没生效 |
| **用户授权范围（scope）** | 你点「同意」那一刻固化 | 后台新开权限后，**必须重新授权**才吃到 |

## 2. 第一次使用（3 步）

```text
① feishu_auth action=authorize_url      → agent 给你一个飞书授权链接，点开同意
② feishu_auth action=status             → 确认 refreshable: true、scope 含 offline_access
③ feishu_drive action=list_files pageSize=5 identity=user   → 能列出你云空间的 5 个文件
```

> 第 ② 步最关键：`refreshable: true` 表示插件能自动续期，不会两小时后又让你重授权。
> 若为 `false`，看 `scope` 里有没有 `offline_access`——没有就让管理员在后台开通并发版，然后重新授权。

设置在哪：DSH 的**设置页 → 飞书 / Feishu**，可填 App ID、看授权状态、发起授权；授权后右上角还有一个悬浮面板显示"是否已授权 / 最近做了什么"。

## 3. 常用任务配方

下面每格都可以直接对着 agent 说。`$1` 之类表示你手里已有的 token/链接。

### 3.1 云空间（`feishu_drive`）

| 你想做什么 | 这样说 |
|---|---|
| 看云空间有什么 | 「列出我飞书云空间根目录的文件，只要 10 个」 |
| 建文件夹 | 「在飞书云空间建一个文件夹叫 2026-10 报告」 |
| 上传本地文件 | 「把 `/tmp/report.pdf` 上传到刚才那个文件夹」 |
| 下载 | 「把飞书里的 `$1` 下载到 `/tmp/`」 |
| 移动 | 「把 `$1` 移到文件夹 `$2` 里」 |
| 看是什么类型 | 「查一下 `$1` 的元信息（是什么类型、什么时候建的）」 |
| 删除 | 「删掉 `$1`（是文档/文件夹/表格）」 |

要点：删除和移动需要 `docType`（`doc` / `docx` / `sheet` / `bitable` / `mindnote` / `file` / `slides` / `wiki` / `folder`）——不确定就说"你先查元信息再操作"。

### 3.2 云文档（`feishu_doc`）

| 你想做什么 | 这样说 |
|---|---|
| 建文档 | 「新建一篇飞书文档，标题『2026-10 周报』」 |
| 把 Markdown 写进去 | 「把下面这段 Markdown 追加进 `$1`：…（可含标题/列表/**表格**/代码块）」 |
| 导入本地文件 | 「把 `/tmp/spec.md` 导入成飞书文档，放到文件夹 `$2`」 |
| 读全文 | 「把 `$1` 的正文读出来给我，我要做摘要」 |
| 看结构 | 「列一下 `$1` 的所有块，告诉我它的章节结构」 |

要点：
- **导入必须给目标文件夹**（飞书不允许导入到根目录）；
- 表格能写，但**列宽由飞书决定**，你不能指定；
- 大文档不要一次读完，先说"只读前 200 行/只看标题层级"。

### 3.3 电子表格（`feishu_sheet`）

| 你想做什么 | 这样说 |
|---|---|
| 建表并写数据 | 「建一个飞书表格，把下面这张表写进 A1 开始：…」 |
| 读某区域 | 「读 `$1` 的 A1:D20，转成 Markdown 表格给我」 |
| 追加一行 | 「在 `$1` 的表尾追加一行：2026-10-28, 完成, 5h」 |
| 加工作表 | 「给 `$1` 加一个工作表，叫『明细』」 |

要点：区域用 A1 记法；多工作表用 `工作表ID!A1:B3` 指定（先 `list_sheets` 拿 ID）。

### 3.4 多维表格（`feishu_bitable`）

| 你想做什么 | 这样说 |
|---|---|
| 建 Base（含字段） | 「建一个多维表格『项目跟踪』，字段：项目名(文本)、负责人(文本)、状态(单选：未开始/进行中/已完成)、进度(数字)」 |
| 插记录 | 「往 `$1` 的 `$2` 表插 5 条记录：…（用 JSON 或表格给我）」 |
| 查询 | 「查 `$1` 里状态＝进行中的记录，按进度倒序，只要前 5 条」 |
| 改一条 | 「把记录 `$3` 的状态改成已完成」 |
| 删一条 | 「删掉记录 `$3`」 |
| 看字段结构 | 「列一下 `$1` 的字段名和类型」 |

要点：
- 新建的 Base **自带一张默认表**（通常叫「数据表」），agent 会按名字挑你要的那张；
- 记录写入用**字段名**作 key（中文名直接写）；
- 单选字段的值必须是该字段已声明的选项之一。

### 3.5 聚合统计（`feishu_query`）

Base 里的"求和/分组/排名"用这个，**不要让 agent 翻页自己算**：

| 你想做什么 | 这样说 |
|---|---|
| 分组计数 | 「统计 `$1` 里各状态的记录数」 |
| 求和/平均 | 「算 `$1` 的工时总和与平均」 |
| Top N | 「按项目分组求工时总和，取前 5」 |
| 条件聚合 | 「只看 10 月的记录，统计每天的条数」 |

服务端算，快且准；结果直接给数字表。

### 3.6 仪表盘（`feishu_dashboard`）

| 你想做什么 | 这样说 |
|---|---|
| 建仪表盘 | 「在 `$1` 里建一个仪表盘『项目看板』」 |
| 加图表 | 「加一个柱状图：按状态分组，统计工时总和」 |
| 改/删块 | 「把那个文本块改名为『说明』」「删掉图表块」 |
| 取图表算好的数 | 「把那个柱状图现在算出来的数字给我」 |

要点：图表用**表名 + 字段名**描述（不用记 id）；仪表盘读、建、改、删各是一个独立权限，缺一个就整组不可用。

### 3.7 知识库（`feishu_wiki`）

| 你想做什么 | 这样说 |
|---|---|
| 看有哪些空间 | 「列一下我的飞书知识库」 |
| 看某空间的节点 | 「列出『$1』空间根目录下的节点」 |
| 拿节点对应的文档 | 「查一下 wiki 节点 `$2` 背后是哪篇文档，把 id 给我」 |

⚠️ 建节点/移动/改标题：能调，但**飞书没有删除 wiki 节点的接口**，建了就删不掉，建议在可弃用的测试空间里做。

### 3.8 消息（`feishu_message`）

| 你想做什么 | 这样说 |
|---|---|
| 发给某人 | 「给 `$open_id` 发一条飞书消息：今天的构建已通过」 |
| 发到群 | 「发到群 `$chat_id`：明早 10 点评审」 |
| 发卡片 | 「发一张交互卡片给 `$open_id`，标题『构建结果』，正文…」 |
| 发富文本 | 「发一条富文本（post）给我自己」 |
| 传图片/文件 | 「把 `/tmp/chart.png` 发给 `$open_id`」 |
| 回复某条 | 「回复消息 `$msg_id`：已收到」 |
| 撤回 | 「撤回 `$msg_id`」 |

要点：
- **谁能发、就得谁能撤**：agent 用哪个身份发，就得用同一身份撤（插件默认会算对）；
- 测试时**先发给自己**（用 `identity=user` 且 `receiveId` 填你的 open_id），确认后再发给别人；
- 群发没有"批量/广播"接口，多人请逐个来，别让它群发。

### 3.9 兜底：任意飞书接口（`feishu_api`）

上面没覆盖的（群管理、通讯录、日历、审批…）可以用它直调开放平台：

```text
「用 GET 调 /contact/v3/users/me，参数 user_id_type=open_id，把结果给我」
「用 DELETE 调 /im/v1/messages/$msg_id，身份用 app」
```

它能做**任何**你有权限的事，包括删除——所以让 agent 调它之前，务必确认路径和参数。

## 4. 怎么把话说清楚（少返工）

| 做法 | 例子 |
|---|---|
| 说明**身份** | 「以我本人身份（identity=user）建文档」——否则可能落到应用空间 |
| 一次一件事 | 「先建 Base，完成后再插数据」而不是"把整套东西都建好" |
| 给它**已有 id** | 直接贴 `document_id` / `base_token` / `chat_id`，别让它猜 |
| 要求**回报链接/ID** | 「建完把 url 和 token 给我」——后续步骤要用 |
| 批量用循环语义 | 「对这 5 个文件依次下载」而不是"下载所有" |
| 不可逆操作先确认 | 「先列清单给我确认，再删」 |
| 大内容走文件 | 「Markdown 太长」时先说"写到 `/tmp/x.md`，然后导入" |

## 5. 结果怎么读

成功时 agent 会说「已建好 + 链接」。想核对细节，让它把**原始返回**给你，结构是：

```
{ ok: true, action: "create", summary: "created …", url?: "https://…", warnings?: [...], data: { … } }
```

- `summary` 一句话结论；
- `url` 有就是可以直接点开的链接；
- `warnings` **一定要看**：最常见的是「没有用户授权，本次以应用身份执行」——那意味着东西落在应用空间、不在你名下；
- `data` 是飞书原始字段（`document_id`、`app_token`、`records`…），后续操作要用里面的 id。

失败时（0.1.1 起）会给出结构化诊断，不是一句糊话：

```
Feishu API error: Unauthorized…
http_status: 400
code: 99991679
path: /base/v3/bases/xxx/dashboards
hint: The app lacks a required data scope… Grant it, then publish a new app version.
detail: {…"required one of these privileges under the user identity: [base:dashboard:create]"…}
```

**看 `hint` 和 `detail`**：`detail` 里那句 `required one of these privileges under the user identity: [xxx]` 就是缺的权限名，照它去后台开。

## 6. 安全与边界（务必知道）

| 事项 | 说明 |
|---|---|
| 它能动你的真实云空间 | 建/改/删文档、表格、Base、消息都是真的。**删除类操作先让它列清单** |
| 密钥不在对话里 | App Secret 存本地凭据库；agent 只拿到"是否已配置"，看不到值 |
| 身份降级会告警 | 没授权时走应用身份，结果里有 warning，别忽略 |
| 建议用测试前缀 | 让 agent 建的测试对象统一叫 `DSH-TEST-…`，跑完让它删 |
| 先只读后写入 | 新环境先跑 `list_files` / `list_spaces` 这类只读调用验证通不通 |
| 群发要克制 | 没有广播接口，多人消息请逐个确认对象 |

## 7. 常见问题（使用视角）

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 所有调用都报 `99991679` | 应用权限没开，或开了**没发版**，或用户授权是旧的 | 后台开权限 → 创建版本发布 → 重新授权 |
| 每两小时就要重新授权 | `scope` 里缺 `offline_access` | 后台开通 + 发版 + 重新授权；之后 `status` 的 `refreshable` 应为 `true` |
| 文档建在"别的地方" | 走了应用身份 | 看结果里的 `warnings`；显式说 `identity=user` |
| `append_markdown` 报 `1770001 invalid param` | 旧版本（<0.1.1）写表格的 bug | 升级到 0.1.1 |
| 导入文档失败 | 没给目标文件夹 | 指定一个文件夹 token |
| `create_field` 报错 | 字段名/类型不合法，或表 id 不对 | 先 `list_tables` / `list_fields` 确认 |
| 撤回消息失败 | 用错了身份（不是发送方） | 让它用 `identity=app` 撤机器人发的消息 |
| `refreshable: true` 但续期失败 | 该标志只表示"记录里有 token"，不代表还有效 | 真跑一次 `feishu_auth action=refresh` 验证 |

## 8. 三个端到端例子

**① 把一份本地 Markdown 变成团队可见的飞书文档**

```text
你：把我本地的 /tmp/2026-10-周报.md 导入成飞书文档，放到文件夹 2026-10 报告里，然后把链接给我
agent：import_file（自动先用 create_folder 定位目标）→ 返回 url + ticket
你：读一遍确认表格没丢
agent：get_raw_content → 确认含表格文本
```

**② 建一个带统计的项目跟踪 Base**

```text
你：建多维表格「项目跟踪」，字段 项目名(文本)/状态(单选：未开始,进行中,已完成)/工时(数字)；
    插 5 条示例数据；然后按状态分组统计条数和工时总和，把结果表格给我
agent：create_app → insert_records → feishu_query(两次聚合) → 返回两张表
```

**③ 生成数据看板并汇报**

```text
你：在「项目跟踪」里建仪表盘「进度看板」，加一个柱状图（按状态分组，工时求和），
    再把图里算出来的数字读给我
agent：create_dashboard → create_block(column) → get_block_data → 返回数字
```

## 9. 做不到的事（别指望 agent 变出来）

- 群管理（建群/拉人/踢人/群公告）、通讯录（用户/部门/搜索）、日历、审批、事件回调——插件没封装，只能 `feishu_api` 手调；
- `feishu_wiki` 删除节点（飞书无此接口）；
- 消息广播（一次发多人）；
- 表格列宽、文档复杂排版（如分栏）由飞书决定，不能精确控制。

完整能力与权限对照表：[`feishu-capabilities.md`](./feishu-capabilities.md)。
